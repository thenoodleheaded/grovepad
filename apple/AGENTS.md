# Grovepad native port — agent guide

The Swift port of Grovepad for macOS, iOS and iPadOS. Read
[the roadmap](../docs/native-port-roadmap.md) first: it holds the decisions,
the scope line and the phase gates. This file is the routing map for work
inside `apple/`. The root [agent guide](../AGENTS.md) still applies (plain
language for the owner, smallest coherent change, tests before eyes).

## Laws that never bend

1. **The web app is the reference.** Every behaviour here is a port of a
   TypeScript file named in the table below. When the two disagree, the port is
   wrong unless the roadmap says otherwise. Read the TypeScript before writing
   Swift; port the key order of every object spread, not just the logic.
2. **Bytes are judged by the pack.** `apple/Conformance/` is generated by the
   web code (`npm run conformance:build`, source in
   `scripts/conformance/conformancePack.ts`). Swift tests read it by path.
   A gate is a passing pack test, never "it looks right".
3. **Foundation only below `GrovepadCore`.** No CryptoKit, no Combine, no
   SwiftUI, no platform conditionals beyond file I/O. SHA-256, JSON and ZIP are
   in-tree. The one exception is Apple's `Compression` framework for raw
   DEFLATE, confined to `Package/ZipArchive.swift` and, for the gzip framing
   of cloud canvas bodies, `Sync/CloudDocumentCodec.swift`. The Supabase SDK
   is imported by `GrovepadCloud` only; `GrovepadCore/Sync` talks to it
   through the `CloudTransport` / `MediaTransport` protocols. The one other
   external code is the Yjs engine (yrs, Rust) behind realtime
   collaboration: `GrovepadYrsFFI.xcframework`, linked by
   `GrovepadCollaboration` only and rebuilt with `Yrs/build-xcframework.sh`
   (never edit `Engine/grovepad_yrs.swift`; it is generated with the binary).
4. **Never `JSONEncoder` for board bytes.** `JSONWriter` reproduces
   `JSON.stringify`; `JSONObject`/`OrderedMap` reproduce JavaScript key order;
   `JSNumberFormatter` reproduces `Number::toString`.
5. **Unknown data survives.** Records are `JSONObject`s with typed accessors
   (`Records.swift`). Never rebuild a record from typed fields when the source
   record exists; mutate the object in place so unknown keys and order survive.
6. **Determinism is injected.** Anything that mints an id or reads the clock
   takes an `IdMinter`/`Clock` parameter (see `Determinism.swift`). The pack
   mints `uuid-0001, uuid-0002, …` and reads `1789000000000` ms.
7. **JavaScript arithmetic.** Use `jsRound` for `Math.round`; coerce with the
   `num`/`text`/`bool` helpers in `Fields/ValueHelpers.swift`, which mirror
   `widgets/fields/valueHelpers.ts` (including `parseFloat` prefix parsing).

## Working method

- Build and test with a private scratch path when another task may be
  running: `swift test --scratch-path .build/<task> --filter <Suite>`.
- Put new helpers in new files. Edits to shared files (`JSON/`, `Model/`,
  `CircuitTypes.swift`) are additive only.
- Field setters and commands take the `IdMinter` as their last parameter
  (`FieldDescriptor.set`, `CommandDescriptor.run`); the web mints inline. The
  pack reset its counter before every setter and command call, so a test
  passes a fresh `.counting()` per call; the engine shares one minter per wave.
- The circuit driver (`Circuit/CircuitDriver.swift`) tells a board load from
  a wire edit by the host's `widgetsVersion`/`connectionsVersion` stamps: both
  bumped in one commit = load/undo → every wire is baselined silently; only
  `connectionsVersion` bumped = a drawn or edited wire delivers now. The web
  keys the same rule on object identity, which values cannot carry.
- Known web quirk, ported faithfully: `remapLegacyRootCanvasId` rebuilds the
  board with `Object.assign`, so a `canvas-origin` board loses its sidecars on
  load (storage law 2 leak). `BoardParser.remapLegacyRootCanvasId` matches
  and says so in its comment; fix the web first, regenerate, then the port.
- Hydrated `canvasViews` keep extra keys on the web (`extraView: "kept"`);
  `Board.canvasViews` is typed, so the pack's `device.canvasViews` is compared
  by canvas id, pan and zoom. Nothing on the web ever reads those extras.
- A failing pack comparison prints the first differing offset
  (`assertSameText`). Fix the port, never the pack; if the web really changed,
  regenerate the pack and review the diff as a format change.
- Keep this file current in the same change whenever a file moves or an owner
  changes, like the root codebase map.

## Porting a widget

Every widget in `GrovepadChrome` follows one pattern, so the ninth is
mechanical. Read the TypeScript renderer, its skin model and its resting face
first (law 1), then:

1. **Registry entry** — already generated in
   `Registry/WidgetRegistryData.generated.swift` from `registry.json`. Do not
   edit it; if a value is wrong, fix the web registry and regenerate. If the
   type carries a `fixed` predicate, add its case to
   `WidgetDefinition.isFixedSize(data:)`.
2. **Renderer struct** — one file `Widgets/<Label>Widget.swift`,
   `public struct XWidget: WidgetRenderer` with `static let type`, a
   `static func skin(_ data:)` that validates the worn skin against the
   catalogue and falls back the way the TypeScript skin model does.
3. **Card body** — `cardBody(_ context:)` in SwiftUI. Read only through
   `context.data` (tolerant reads in `Widgets/WidgetDataReads.swift`). Write
   only through `context.update { data in … }` (in place, law 5) and
   `context.runCommand(key)` / the field setter from `fieldDescriptor`, so a tap
   and a wire never disagree. Item ids come from `context.mint`. Skins the
   port does not draw yet render the default body with a one-line note and
   leave their `skinStates` pocket untouched.
4. **Resting face model** — `restingFace(_ widget:)` returns a
   `RestingFaceModel` built exactly as the web face builder does (icon, note,
   rows, boolean, metric, text, clock, chart, stars, columns, grid, bars,
   gauge, chips, lines, chain, split, canvas; `palette`, `image`, `timeline`
   and `paper` are not ported — no in-scope widget folds to them). An empty
   card is `.icon`. The tile size is computed by `RestingFaceMeasure` from
   the same constants as `restingFace.ts`; only the text estimate differs
   (6.2 pt per character). The title-row mark comes from `WidgetSymbols`
   (`Shell/WidgetSymbols.swift`), one SF Symbol per type standing in for the
   registry's lucide icon; add the type there.
5. **Resting body** — `restingBody` is always
   `WidgetRestingFaceView(context: context)`; never a bespoke tile.
6. **Skins** — the skin field and catalogue come from the definition;
   `BoardDocument.setSkin` writes it. Wear the skin's accent through
   `context.accent`; never hand-pick a hue.
7. **Register** — add the renderer to `WidgetRendererRegistry.renderers` and
   the type to `phaseThreeTypes` (or its successor list) in
   `Tests/GrovepadChromeTests/Support/ChromeFixtures.swift`. The gate loops
   (`WidgetGateTests`) then judge it: creatable, editable, undoable, resizable,
   skinnable, persists, renders resting and live. Add a case to
   `testRestingFaceGrammar` for the face it folds to.
8. **Touch answers** — record the four answers below in one line.
